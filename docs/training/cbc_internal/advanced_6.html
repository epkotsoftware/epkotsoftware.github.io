1. フォームを作る

名前を入力して登録ボタンを押すと、DBに追加されるようにします。まずは入力欄から作ります。

index.php — Visual Studio Code
index.php
1 2 3 4
<form method="post" action="">
  <input type="text" name="name">
  <button type="submit">登録</button>
</form>
部分 意味
method="post" どうやって送るか。下で説明します
action="" どこへ送るか。空にすると自分自身に送られます
name="name" 受け取るときの名前。PHP側で $_POST['name'] になります
type="submit" 押すとフォームを送信するボタン
name が無いと届かない
<input> に name を書き忘れると、入力しても値が送られません。画面上は何も変わらないので、気づきにくいところです。
「動かないときは、まず name を確認する」と覚えてください。

GET と POST

送り方は2つあります。今回は POST を使います。

GET index.php?name=佐藤

URLに値が付く。
ブックマークできる。履歴に残る。
検索など「取ってくる」ときに使う。

POST index.php

URLに出ない。裏側で送られる。
長いデータも送れる。
登録や更新など「変える」ときに使う。

なぜ登録は POST なのか
GET だと URLをコピーして誰かに送っただけで、その人の画面でも登録が走ります。ブラウザの「戻る」でも、もう一度登録されます。
データを変える操作は POST。これは決まりごとではなく、事故を防ぐための決まりです。
パスワードのように人に見せたくない値も、URLに出ないPOSTで送ります。
POST なら安全、ではない
URLに出ないだけで、通信の中身は誰でも見られます。開発者ツールのNetworkタブを開けば、送った値がそのまま表示されます。
本当に守るなら HTTPS（通信そのものを暗号化する仕組み）が要ります。POST は「隠す」ためのものではありません。

index.php に名前を入力するフォームを追加してください。
入力欄と登録ボタンを1つずつ置きます。見た目は自分のCSSファイルに書いてください。
作れたら、何か入力して登録ボタンを押し、開発者ツールの Network タブで送られているか見てみましょう。まだDBには入りません。 index.php（穴埋め） <form method="xxxxxx" action=""> <!-- 登録に使う送り方は？（この章） --> <input type="text" xxxxxx="name"> <!-- PHP側で受け取るための属性は？ --> <button type="submit">登録</button> </form>
答え index.php <form method="post" action=""> <input type="text" name="name">

2. 送られた値を受け取る

送られた値は $_POST という配列に入っています。PHPが自動で用意してくれるので、自分で作る必要はありません。

HTML側 <input type="text" name="name">
PHP側 $_POST['name']
名前が一致していないと届かない
HTML側の name="name" と、PHP側の $_POST['name']。この2つは必ず同じ文字にします。
片方だけ直して、もう片方を直し忘れる。これが登録できない原因の大半です。

押されたときだけ処理する

ページを開いただけでは登録したくありません。ボタンが押されたときだけ動くようにします。

index.php — Visual Studio Code
index.php
1 2 3
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // ここに登録の処理を書く
}
$_SERVER['REQUEST_METHOD']
いまどうやって開かれたかが入っています。
URLを直接叩いて開いたときは 'GET'、フォームの送信ボタンで来たときは 'POST' です。
これで「ボタンが押されて来た」と分かります。
== ではなく ===
フロントエンド初級#4 で出てきた比較です。イコールが2つと3つで意味が違います。
== は「だいたい同じ」。型が違っても、変換して同じなら通します。'1' == 1 は true です。
=== は「型まで同じ」。'1' === 1 は false になります。
迷ったら === を使ってください。思わぬ値が通り抜けて、原因の分からない不具合になります。この教材では最後まで === と !== しか使いません。

空のまま送られたら

何も入力せずにボタンを押されることがあります。空の名前を登録しても意味がありません。

index.php — Visual Studio Code
index.php
1 2 3 4 5 6 7
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $name = trim($_POST['name'] ?? '');

    if ($name !== '') {
        // ここで登録する
    }
}
書く場所は、HTMLより上
この if は、ファイルのいちばん上の <?php ブロックの中に書きます。#5 で書いた $pdo->query(...) より前です。
フォームを足した勢いで </form> の下に書くと、次の章で
Warning: Cannot modify header information - headers already sent
というエラーが出ます。登録の処理は上、画面は下。この順番を崩さないでください。
<?php ここから DBにつなぐ（#5で書いた） 送られた値を受け取る　← いま書くのはここ 一覧を取ってくる（#5で書いた） ?> ここまで
HTML <form>　← 演習1で足した <div id="drag-area"> の foreach
書き方 やっていること
?? '' もし無かったら空文字にする。キーが存在しないときのエラーを防ぎます
trim() 前後の空白を削る。スペースだけ入力された場合に空とみなせます
!== '' 空でなければ通す
?? は「無かったら」
null合体演算子といいます。$a ?? $b で「$a があればそれ、無ければ $b」という意味です。
$_POST['name'] は、フォームを通らずにアクセスされたとき存在しません。そのまま使うとエラーになるので、?? '' で受け止めます。
送られてくる値は、全部「文字」
#5 でDBから読んだときは int(810) のように型が付いていました。フォームから来る値は違います。
数字だけを入力しても、$_POST['name'] は string です。HTMLには型が無いからです。
マークアップ中級#7 でやった '10' + 5 の問題は、ここで起きます。数として扱いたいときは (int) を付けて変換します。この書き方は #7 でも何度も出てきます。
入力チェックは、必ずPHP側でもやる
HTMLには required という属性があり、これを付けるとブラウザが空のまま送らせません。便利ですが、それだけでは足りません。
開発者ツールで required を消せば、空のまま送れてしまいます。フォームを通さず直接データを送ることもできます。
ブラウザ側のチェックは親切のため。PHP側のチェックは安全のため。両方要ります。
演習2
ボタンが押されたときだけ、入力された名前を画面に表示してください。まだDBには入れません。
空のまま押したときは、何も表示されないようにします。
表示するときは #5でやった htmlspecialchars を忘れずに。 index.php（穴埋め） if ($_SERVER['REQUEST_METHOD'] === 'xxxxxx') { /* ボタンで来たときの値は？（この章） */ $name = xxxxxx($_POST['name'] ?? ''); /* 前後の空白を削る関数は？ */ if ($name !== '') { echo htmlspecialchars($name); } }
答え index.php if ($_SERVER['REQUEST_METHOD'] === 'POST') { $name = trim($_POST['name'] ?? '');

3. 安全に登録する ― prepare

いよいよDBに書き込みます。ですがその前に、絶対にやってはいけない書き方を先に見てください。

やってはいけない書き方

✕ 値をそのまま繋ぐ $sql = "INSERT INTO sortable (name) VALUES ('" . $name . "')"; $pdo->query($sql);

動きます。ですが、これで作るとテーブルを消されます。

○ prepare を使う $stmt = $pdo->prepare( 'INSERT INTO sortable (name) VALUES (:name)' ); $stmt->execute([':name' => $name]);

値がどんな文字でも、SQLとしては解釈されません。

なぜ消されるのか

左の書き方だと、入力された文字がそのままSQLの一部になります。名前の欄にこう入れられたらどうなるか、追ってみてください。

1
入力された文字 '); DROP TABLE sortable; --
↓ そのまま繋がれる
2
出来上がったSQL INSERT INTO sortable (name) VALUES (''); DROP TABLE sortable; --')
↓ DBはこう読む
3
2つの命令として実行される INSERT INTO sortable (name) VALUES (''); DROP TABLE sortable; -- ') ← ここから後ろはコメント扱いで無視される
SQLインジェクション
injection は「注入」という意味です。値のふりをしてSQLの命令を注入されるので、この名前が付いています。
テーブルを消される、他人のデータを抜かれる、パスワードを書き換えられる。実際に起きている事故で、いまも起き続けています。
マークアップ中級#6 で出てきた XSS と同じ構造です。外から来た文字を、そのまま信じて使ったのが原因です。

prepare は何をしているのか

prepare は、SQLの骨組みだけを先にDBへ渡します。値はあとから別便で送ります。

1 prepare 骨組みを渡す
VALUES (:name)
2 DBが解析 「ここは値の置き場所」
と決まる
3 execute 値を送る
もう命令にはならない
順番が守ってくれる
SQLの形が先に決まっているので、あとから来た値がどんな文字でも、命令として読まれることはありません。DROP TABLE と入力されても、そういう名前として登録されるだけです。
「危ない文字を消す」のではなく、「値と命令を最初から分けておく」という考え方です。
:name のような書き方
プレースホルダといいます。「あとで値が入る場所」という印です。
? を使う書き方もありますが、名前が付いているほうが読みやすいので、こちらを勧めます。値が増えたときに順番を間違えません。
名前付き（勧める） '… VALUES (:name, :left)' $stmt->execute([ ':name' => $name, ':left' => $left, ]);
? を使う書き方 '… VALUES (?, ?)' $stmt->execute([ $name, $left, ]); // 順番を間違えると入れ違う
迷ったら prepare
「値が混ざらないから query でいい」と判断できるうちはいいのですが、判断を間違えると事故になります。
外から来た値が1つでも入るなら prepare。実務では「全部 prepare にしておけ」という方針の現場も多くあります。
演習3
入力された名前を、実際にDBへ登録してください。
登録できたら画面を開き直して、一覧に増えているか確認します。
確認できたら、名前の欄に '); DROP TABLE sortable; -- と入れてみてください。そういう名前の札が1つ増えるだけなら、正しく書けています。
登録した札は すべて同じ場所（左上）に重なります。これは left_x と top_y に同じ値を入れているためです。ドラッグして動かせるようにするのは、次のページでやります。 index.php（穴埋め） if ($name !== '') { $stmt = $pdo->xxxxxx('INSERT INTO sortable (name, left_x, top_y) VALUES (:name, 20, 20)'); /* 骨組みを先に渡すメソッドは？ */ $stmt->xxxxxx([':name' => $name]); /* 値を送って実行するメソッドは？ */ }
答え index.php $stmt = $pdo->prepare('INSERT INTO sortable (name, left_x, top_y) VALUES (:name, 20, 20)'); $stmt->execute([':name' => $name]);

4. 二重登録を防ぐ

登録できたと思います。ですが1つ問題が残っています。登録したあと、ブラウザで再読み込みしてみてください。

フォームを再送信しますか？
このページを表示するには、以前入力したデータを再送信する必要があります。

この確認が出て、OKを押すともう1件登録されます。同じ名前の札が2つ、3つと増えていきます。

なぜこうなるのか
ブラウザは「直前にやったこと」を覚えていて、再読み込みでもう一度やります。
登録ボタンで来た場合、直前にやったことは「POSTで送信した」です。だから再読み込みすると、また送信されます。
戻るボタンで戻ってきたときも同じことが起きます。

登録したら、自分自身へ飛ばす

解き方はひとつです。登録が終わったら、すぐに別のアクセスに切り替えます。

index.php — Visual Studio Code
index.php
1 2 3 4 5 6 7
if ($name !== '') {
    $stmt = $pdo->prepare('INSERT INTO sortable (name, left_x, top_y) VALUES (:name, 20, 20)');
    $stmt->execute([':name' => $name]);

    header('Location: index.php');
    exit;
}
行 やっていること
header('Location: …') ブラウザに「そのURLへ行き直して」と伝えます
exit; ここで止める。書かないと、この先の処理も動いてしまいます
✕ そのまま表示 POST で来る ↓ 登録する ↓ そのまま画面を出す 再読み込み → また POST
○ 飛ばしてから表示 POST で来る ↓ 登録する ↓ GET で開き直させる ↓ 画面を出す 再読み込み → GET のまま
PRG パターン
POST → Redirect → GET の頭文字です。「ポスト・リダイレクト・ゲット」と読みます。
Redirect（リダイレクト）は「別のURLへ行き直させる」ことです。
登録・更新・削除では、ほぼ必ずこの形にします。フレームワークを使うようになっても、考え方は変わりません。
header より前に出力しない
header() は、画面に何か出す前でないと動きません。1文字でも先に出ていると、こんなエラーが出ます。
Warning: Cannot modify header information - headers already sent
<?php より前の空行や空白でも出力扱いになります。エラーが出たら、まずファイルの先頭を確かめてください。
