1. フレームワークとは何か

いままで書いてきたコードを思い出してください。毎回、同じことを書いていました。

DB につなぐ エラーの設定をする SQL を書く prepare して execute する 取ってきた配列を foreach で回す htmlspecialchars で囲む
どのアプリでも必要になるもの
DB接続、フォームの受け取り、エスケープ、ページの組み立て。作るものが違っても、この土台は同じです。
その土台をあらかじめ用意しておいたものが、フレームワークです。

骨組みだけ、先にできている

framework は「骨組み」という意味です。家でいえば、柱と梁ができている状態。あとは間取りを決めて、内装をやるだけになります。

素の PHP
DB接続を自分で書く SQLを自分で書く エスケープを自分で書く ルーティングを自分で作る ファイル構成を自分で決める

全部できる。ただし全部やらないといけない。書き忘れると事故になります。

Laravel
DB接続は設定ファイルに書くだけ SQLはメソッドで書ける エスケープは自動 ルーティングの仕組みがある ファイルの置き場所が決まっている

決まった場所に、決まった書き方で置く。そのぶん覚えることがあります。

フレームワークは万能ではない
「Laravel を使えば楽になる」というのは半分だけ正しいです。決まりごとを覚えるまでは、素の PHP より遅くなります。
それでも使うのは、人が増えても同じ形で書けるから、よくある事故を仕組みで防げるからです。
1人で小さいものを作るなら、素の PHP のほうが速いこともあります。道具の使い分けです。
なぜ Laravel なのか
PHP のフレームワークは他にもあります（Symfony、CakePHP、CodeIgniter など）。
Laravel は日本の求人でいちばん見かけるものです。情報も多く、困ったときに調べやすい。最初の1つとして選びやすいという理由です。

「規約」という考え方

Laravel には「こう書けば、こう動く」という決まりがあります。設定を書かなくても、名前から推測してくれます。

作るもの 置き場所 対応するテーブル
Sortable クラス app/Models/Sortable.php sortables（複数形）
Department クラス app/Models/Department.php departments
単数形と複数形
クラス名は単数、テーブル名は複数。これが Laravel の決まりです。
Sortable と書けば、勝手に sortables テーブルを見に行きます。設定は書きません。
フロントエンド編では sortable（単数）という名前でしたが、Laravel では複数形にします。規約に合わせたほうが、あとの記述が短くなります。
設定より規約
「Convention over Configuration」という言葉があります。いちいち設定を書かせるのではなく、決まりに従わせるという考え方です。
決まりを覚えるまでは窮屈ですが、覚えたあとは書く量が減ります。

2. Laravel を動かす

環境は用意してあります。3つのコマンドで動きます。

コンテナを起動する

05_laravel/docker/ に移動して、コンテナを立ち上げます。

$ cd 05_laravel/docker $ docker compose -f docker-compose-dev.yml --env-file .env up -d
フロントエンド編とは別のポート
同時に動かせます。ぶつからないように番号を分けてあります。
フロントエンド編 バックエンド編
画面 8001 8026
phpMyAdmin 8888 8889
DB cri_sortable cbc_laravel

ライブラリを入れる

Laravel はたくさんの部品の集まりでできています。その部品を取ってきます。

$ docker exec training-laravel-web composer install
composer とは
PHP のライブラリ管理ツールです。composer.json に「何が必要か」が書いてあり、composer install でそれを取ってきます。
取ってきたものは vendor/ に入ります。8000 を超えるファイルになるので、Git には入れません（.gitignore に書いてあります）。
他の人は composer install を打てば同じものが揃います。だから配布しなくていいのです。
数分かかります
初回は 100 個近いライブラリを取ってきます。止まったように見えても待ってください。
Generating optimized autoload files と出れば終わりです。

テーブルを作る

Laravel はセッション（ログイン状態などを覚えておく仕組み）をDBに保存します。そのためのテーブルが要ります。

$ docker exec training-laravel-web php artisan migrate
Connection refused と出たら、待ってからもう一度
up -d はコンテナを起動しただけで、MySQL が受け付けられる状態になるまでには少し時間がかかります。
早すぎると、こうなります。
SQLSTATE[HY000] [2002] Connection refused
不具合ではありません。10秒ほど待って、もう一度打ってください。
2回目以降は composer install が速く終わるので、ここに引っかかりやすくなります。
これを飛ばすとエラーになる
先に画面を開くと、こうなります。
SQLSTATE[42S02]: Base table or view not found:
1146 Table 'cbc_laravel.sessions' doesn't exist
「sessions テーブルが無い」と言っています。migrate を実行すれば直ります。
順番を守ってください。

画面を開く

ブラウザで localhost:8026 を開きます。Laravel の初期画面が出れば成功です。

表示できたら、わざと止めてみましょう。docker compose down でコンテナを落として、画面が開かなくなることを確認します。
もう一度 up -d で戻してください。2回目は速いはずです（composer install は不要）。
動かないときに見る場所
画面が真っ白… storage/logs/laravel.log にエラーが出ています。

そもそも繋がらない… docker ps でコンテナが動いているか確認してください。

3. フォルダの見方

Laravel はファイルがたくさんあります。全部を覚える必要はありません。この研修で触るのは6つだけです。

05_laravel/app/ ├── app/ │ ├── Models/ ← DBとやり取りする │ └── Http/Controllers/ ← 処理の流れを書く ├── database/ │ ├── migrations/ ← テーブルの設計図 │ └── seeders/ ← 最初に入れるデータ ├── resources/views/ ← 画面（Blade） ├── routes/web.php ← URLと処理の対応 ├── public/ ← 公開フォルダ（CSS・JS・画像） ├── config/ ← 設定 ├── storage/ ← ログ・キャッシュ ├── vendor/ ← composer で入れた部品 └── .env ← 接続情報など
赤いところだけ触ります
Models / Controllers / migrations / seeders / views / web.php。この6つです。
それ以外はLaravel が用意したもので、いまは触りません。

public だけが外から見える

ブラウザからアクセスできるのは public/ の中だけです。

フロントエンド編
htdocs/ ├── index.php ← 見える ├── config.php ← 見える └── Controller/ └── Connect.php ← 見える

全部が公開フォルダの中にありました。DBのパスワードが書かれたファイルも、URLを打てば辿り着けます。

Laravel
app/ ├── public/ │ └── index.php ← 見える ├── app/Models/ ← 見えない ├── .env ← 見えない └── vendor/ ← 見えない

公開するものと、しないものが分かれています。設定ファイルは外から見えません。

入口は1つだけ
どのURLを開いても、最初に動くのは public/index.php だけです。
そこから routes/web.php を見て、「このURLならこの処理」と振り分けます。
フロントエンド編では index.php sortable2/index.php とファイルの数だけ入口がありました。Laravel は1つです。
.env は配布しないのが普通
.env にはDBのパスワードが書かれています。実務では .gitignore に入れて、Git に上げません。
この研修では学習用なので、あらかじめ入れてあります。実務ではそうしない、と覚えておいてください。

4. artisan ― 手を動かす道具

Laravel には artisan（アルチザン）というコマンドが付いています。ファイルを作ったり、DBを操作したりできます。

$ docker exec training-laravel-web php artisan list

使えるコマンドが一覧で出ます。この研修で使うのは、次のものです。

コマンド やること 使う回
make:migration テーブルの設計図を作る #2
migrate 設計図どおりにテーブルを作る #2
make:model Model のファイルを作る #3
make:controller Controller のファイルを作る #3
make:seeder 最初に入れるデータを作る #2
route:list URLの一覧を見る #2
なぜコマンドで作るのか
手で新しいファイルを作ってもいいのですが、置き場所と書き出しが決まっています。
make:model Sortable と打てば、正しい場所に、正しい形でファイルができます。名前空間の書き間違いも起きません。
コンテナの中で実行する
php artisan はコンテナの中で動かします。手元のパソコンには PHP が入っていないかもしれません。
毎回 docker exec training-laravel-web を頭に付けるか、コンテナに入ってから打ちます。
$ docker exec -it training-laravel-web bash # php artisan list # これ以降は php artisan だけでいい # exit # 出るとき
演習2
php artisan list を実行して、コマンドの一覧を出してください。
次に php artisan route:list を打ってみましょう。いま登録されているURLが1つだけあるはずです。
それが routes/web.php に書かれているものです。ファイルを開いて見比べてください。 routes/web.php use Illuminate\Support\Facades\Route; Route::get('/', function () { return view('welcome'); });
この1行が読めれば十分です
Route::get('/', ...) は「/ を GET で開いたら、この処理」という意味です。
view('welcome') は resources/views/welcome.blade.php を表示するということ。
